# 0. UI ARCHITECTURE PRINCIPLE

## 0.1 Core Model

UI iFlux = **Snapshot-first + Streaming-delta UI**

| Layer         | Role                              |
| ------------- | --------------------------------- |
| REST Snapshot | nạp baseline authoritative        |
| WebSocket     | delta stream incremental          |
| **Entity Store** | client-side projection — giữ state merge từ snapshot + WSS (§0.5) |
| UI Chrome     | scroll, pulse, navigation — ephemeral/preserve rules §1.4 |

**Hai tầng merge (không nhầm):**

| Tầng | Trách nhiệm |
| --- | --- |
| **Transport (WSS Gateway)** | Batch 200ms; drop intermediate ticks **per channel** (Contract §4.3) |
| **UI projection** | Merge event vào **entity key** (`ticker`, `sector_id`, …) — §0.5 |

---

## 0.2 UI Golden Rule — Business vs State Logic

> UI **KHÔNG có business logic**. UI **CÓ state logic** (projection layer xác định).

**Business logic (CẤM ở UI):**

* Không tính flow, Ig, Pg, rank, strength, trend
* Không classify subject
* Không derive ranking

👉 Domain logic nằm ở SVC layer (Engine + API).

**State logic (CHO PHÉP — bắt buộc deterministic):**

* So sánh snapshot cũ/mới → patch field đổi
* Merge WSS event theo entity key
* Dedup `event_id` (INV-E01)
* Preserve / reset UI chrome theo §1.4
* Pulse animation (presentation only — §0.4.1)

---

## 0.3 Core Golden Rules (Runtime)

| Rule | Mô tả |
| --- | --- |
| **Snapshot-first** | Luôn nạp snapshot REST trước khi mở WebSocket |
| **No Business Logic** | UI không tính lại giá trị thị trường — chỉ hiển thị field từ API/WSS |
| **Ticker-centric** | Entity key đồng bộ Backend: `ticker`, `sector_id`, `ecosystem_id` |
| **State Patching** | Patch theo entity — không re-render toàn màn hình |
| **UI-PROJECTION** | Snapshot + delta phải converge cùng một entity map — không fork state theo channel |

> **INV-PER** (File 03) = persistence job separation (flush vs rollup) — **không** map trực tiếp UI layer. UI enforce **hậu quả hiển thị** qua **UI-PROJECTION** + §1.4 rehydration.

## 0.4 Runtime Visual Rules

> **Nguồn:** IA §20 (5 UI states); pulse/stale/degraded tokens → **06_DESIGN_SYSTEM v1.1.4** §1.5, §2.2, §5.

### 0.4.1 Real-time Pulse (Nháy màu giá)

**Trigger:** WSS `price_update` hoặc `index_update` (chỉ khi **không** ở Degraded Mode — xem §10.3).

| Điều kiện | Hành vi |
| --- | --- |
| Giá mới > Giá cũ | Background cell nháy xanh (opacity 20% → 0% trong **500ms**) |
| Giá mới < Giá cũ | Background cell nháy đỏ (opacity 20% → 0% trong **500ms**) |
| Update liên tiếp < 500ms | Restart animation từ đầu |

**Token:** `--pulse-green`, `--pulse-red` — **06 §1.5** (opacity 20%, 500ms ease-out).

**Rehydration:** pulse state = **ephemeral** — reconnect/resume → **reset** (§1.4).

### 0.4.2 Stale Data Handling

UI **không** tự tính `staleness_ms` — dùng `meta.staleness_ms` từ API response (04_API §2.1).

| Snapshot endpoint | `max_staleness_ms` client chấp nhận |
| --- | --- |
| `/snapshot/market` | **2000** |
| `/snapshot/watchlist` | **4000** |
| `/snapshot/sectors`, `/snapshot/ecosystems` | **6000** |

Vượt ngưỡng tương ứng:

* Opacity dữ liệu giảm xuống **60%**
* Icon Warning nhỏ cạnh ticker / header index
* Có thể kích hoạt silent refetch (không reset UI stack)

> **Lưu ý:** Ngưỡng circuit breaker degraded (Tech Spec §16.1 — 10s không tick) **khác** ngưỡng stale UI trên — không gộp thành một con số.

### 0.4.3 Loading (IA §20)

* **LOADING:** Skeleton UI đúng kích thước component — không layout nhảy
* **READY / EMPTY / ERROR / LOCKED:** theo IA §20 bảng trạng thái

## 0.5 UI State Model (Entity-Based)

> Dev FE **MUST NOT** invent state shape — projection map dưới đây là baseline GĐ1.

```typescript
UI_STATE = {
  meta: {
    connection: "connected" | "reconnecting" | "disconnected",
    degraded: boolean,              // từ header X-Data-Status
    data_as_of: string | null,      // từ API meta/body
    last_event_id: Record<string, string>  // dedup key per stream
  },

  entities: {
    stocks: {
      [ticker: string]: {
        price: number,
        change_pct: number,
        volume: number,
        ts: string,
        sticker?: {
          sector_rank: number,
          sector_pg: number,
          eco_rank?: number,
          strength?: number,
          trend?: "up" | "down" | "flat"
        },
        flow?: {
          [subject: string]: { buy: number; sell: number; net: number; ts: string }
        }
      }
    },
    sectors: {
      [id: number]: {
        ig: number,
        pg: number,
        breadth_up: number,
        breadth_down: number,
        rank?: number,
        ts: string
      }
    },
    ecosystems: {
      [id: number]: { /* cùng shape sectors */ }
    }
  },

  watchlist: {
    tabs: Array<{ tab_id: string; name: string; version: number }>,
    items: Record<string, Array<{ ticker: string; order: number; version: number }>>,
    pendingEdit: null | { tab_id: string; op: "add" | "remove" | "reorder" }
  },

  alerts: Array<{
    id: string;
    state: "ACTIVE" | "TRIGGERED" | "PAUSED";
    version: number;
    /* fields từ GET /alerts */
  }>,

  ui: {
    scroll: Record<screenKey, number>,   // preserve — §1.4
    pulse: Record<fieldKey, number>     // ephemeral animation timers — reset on reconnect
  }
}
```

### 0.5.1 Event → Entity merge rules

| WSS `type` | Channel pattern | Patch target |
| --- | --- | --- |
| `price_update` | `stock:{ticker}` | `entities.stocks[ticker].{price, change_pct, volume, ts}` |
| `index_update` | `index:sector:{id}` | `entities.sectors[id].{ig, pg, breadth_up, breadth_down, ts}` |
| `index_update` | `index:ecosystem:{id}` | `entities.ecosystems[id].…` |
| `flow_update` | `flow:{entity}:{id}:{subject}` | `entities.{entity}s[id].flow[subject]` |
| `sticker_update` | `sticker:user:{user_id}` | `entities.stocks[data.ticker].sticker` |

**Quy tắc:** Một ticker có thể nhận event từ **nhiều channel** — UI state **một** record `entities.stocks[ticker]`, merge từng field, không tách state theo channel.

### 0.5.2 Snapshot hydrate

* REST snapshot **seed** entity map (authoritative baseline)
* WSS delta **patch** entity map (không replace toàn map trừ full re-login)
* Reconnect: snapshot patch diff → entity map (§1.2)

### 0.5.3 Source-of-truth precedence (LOCKED)

> Dev **MUST NOT** merge snapshot và WSS theo thứ tự arrival tùy ý.

| Tình huống | Precedence |
| --- | --- |
| **Steady-state** (WSS connected) | WSS delta patch lên Entity Store; snapshot chỉ dùng lúc boot / đổi màn |
| **Reconnect / resume** | **Snapshot ALWAYS overrides WSS** — snapshot fields ghi đè Entity Store trước khi nhận delta mới |
| **Conflict cùng field** | `ts` / `data.as_of` từ snapshot thắng nếu snapshot mới hơn hoặc đang trong reconnect window |
| **409 SYNC_CONFLICT** | Server GET response thắng local watchlist/alert edits (§10.4) |

**Cấm:** apply WSS patch lên entity field đã được snapshot ghi đè trong cùng reconnect cycle trước khi resubscribe xong.

# 1. GLOBAL APP FLOW

## 1.1 App lifecycle

```id="9c4xq7"
BOOT
 → AUTH CHECK
 → FETCH SNAPSHOT (parallel: /snapshot/market + /snapshot/watchlist nếu đã login)
 → HYDRATE entities.* từ snapshot
 → RENDER (Skeleton → Content)
 → CONNECT WSS
 → SUBSCRIBE channels theo màn hình
 → STREAM UPDATES (entity patch + pulse)
```

---

## 1.2 Reconnect flow

> **SoT:** Tech Spec §8.5 — snapshot bắt buộc trước khi subscribe lại; **State Patching** — không flicker.

```id="3v8k2m"
WSS DROP
 → hiện indicator nhẹ "Đang kết nối lại..."
 → apply §1.4 (preserve scroll; reset pulse)
 → BUFFER OFF / DISCARD inbound WSS (xem Order Guarantee bên dưới)
 → SILENT SNAPSHOT (/snapshot/* theo màn hình đang mở)
 → OVERRIDE entities.* từ snapshot (§0.5.3 — snapshot wins)
 → PATCH UI chỉ field diff vs pre-reconnect (tránh flicker)
 → RESUBSCRIBE WSS
 → nhận delta mới sau resubscribe
 → pulse chỉ trên entity field vừa thay đổi (nếu không degraded)
```

**Order Guarantee (bắt buộc — bug class RT lớn):**

1. Khi reconnect bắt đầu → **ngừng apply** mọi WSS frame vào Entity Store
2. WSS events nhận **trước** khi snapshot patch hoàn tất → **MUST discard** (không merge, không queue replay)
3. Chỉ apply WSS **sau** snapshot override + resubscribe thành công
4. Thứ tự cứng: `discard stale WSS → snapshot override → resubscribe → accept new WSS`

**Cấm:** reset UI stack / re-render full tree / unmount screen khi reconnect.

---

## 1.3 App resume từ Background

Áp dụng pattern tương tự §1.2 cho Watchlist và màn hình đang mở (cùng Order Guarantee §1.2):

1. Giữ UI hiện tại (không blank) — §1.4 preserve scroll
2. Reset pulse timers; discard WSS until snapshot override xong
3. Silent GET snapshot tương ứng → override `entities.*` (§0.5.3)
4. Patch UI field diff; resubscribe WSS nếu connection bị drop
5. Pulse **chỉ** entity field thay đổi so với trước background

---

## 1.4 Rehydration Boundary (Reconnect / Resume / Degraded recovery)

> **Thiếu bảng này → UI unpredictable khi reconnect.** Bắt buộc implement đúng.

| Concern | Hành vi | Ghi chú |
| --- | --- | --- |
| **Scroll position** | **preserve** | Per screen key trong `ui.scroll` |
| **Navigation stack** | **preserve** | Không pop route khi reconnect |
| **Animation pulse** | **reset** | Hủy timer cũ; không replay pulse lịch sử |
| **Entity market data** | **patch** | Snapshot authoritative; merge diff vào `entities.*` |
| **Watchlist local edits** | **conflict resolve** | Pending edit + 409 → §10.4; không silent merge local |
| **Watchlist server list** | **overwrite** | Sau GET/snapshot — order theo server |
| **Alert form draft** | **abort on 409** | §10.4; giữ draft nếu chưa submit |
| **WSS subscription list** | **rebuild** | Resubscribe channels — không nhầm với UI stack |
| **Auth token** | **preserve** | Ephemeral exception |
| **Degraded banner** | **update** | Theo header/API response mới nhất |
| **Dedup registry** | **preserve** | `last_event_id` — tránh double-apply sau reconnect |

# 9. REAL-TIME STREAMING RULES (CRITICAL)

## 9.1 Event-to-UI mapping

| Event (WSS) | Entity target | UI Component | Hành vi đặc biệt |
| --- | --- | --- | --- |
| `price_update` | `entities.stocks[ticker]` | Stock Card / Price Row | Patch + Pulse §0.4.1 |
| `index_update` | `entities.sectors[id]` | Market Header / Index | Patch Ig, Pg + Pulse |
| `flow_update` | `entities.*.flow[subject]` | Flow Panel (Premium) | Patch net/buy/sell |
| `sticker_update` | `entities.stocks[ticker].sticker` | Watchlist Badge | Rank, Strength ngay |
| `rebuilding` | `meta.connection` | Subtle overlay | Spinner: "Đang đồng bộ dữ liệu phiên..." |
| `error` | — | Toast / inline | Theo `code` |

---

## 9.2 UI update rule

> UI update MUST be idempotent per `event_id` (INV-E01)

---

## 9.3 Rendering rule

* Gateway batch 200ms per channel → client nhận latest frame
* UI merge vào **entity map** (§0.5) — không re-render full tree
* per-component update only

---

## 9.4 Degraded mode — tách Transport vs UI Policy

Khi `X-Data-Status: degraded` (§10.3):

| Layer | Hành vi |
| --- | --- |
| **Transport** (Tech Spec §16.1) | WSS Gateway **dừng push RT** — không push stale ticks |
| **API** | Header `degraded` + `data_as_of`; REST vẫn serve last valid snapshot |
| **UI policy** | Sticky banner §10.3; **tắt pulse** §0.4.1; giữ `entities.*` last-known; không animate như market live |

# 10. ERROR & FALLBACK UI

## 10.1 Network fallback

| State            | UI                  |
| ---------------- | ------------------- |
| WSS disconnected | indicator "Đang kết nối lại..." (subtle) |
| snapshot fail    | cached last state + nút Thử lại |
| partial data     | skeleton UI (IA §20 LOADING) |

---

## 10.2 Error mapping

| API error | UI |
| --- | --- |
| 401 | login screen |
| 403 | upgrade modal |
| 409 `SYNC_CONFLICT` | xem §10.4 |
| 429 | cooldown message |
| 503 maintenance | banner toàn app (ADM-OPS-005) |

---

## 10.3 Degraded Mode UI

> **Trigger:** Header `X-Data-Status: degraded` hoặc `503 MAINTENANCE` (BRD §22.3, Tech Spec §16.1)

| Hành vi | Chi tiết |
| --- | --- |
| **Sticky Banner** | Ngay dưới Top Nav — màu warning |
| **Nội dung** | "Kết nối sàn gián đoạn. iFlux đang hiển thị giá cuối cùng hợp lệ." |
| **Pulse** | Vô hiệu hóa §0.4.1 (UI policy) |
| **Watchlist / Alert** | Vẫn xem được nếu đã login (BR-CON-05) |
| **Recovery** | Banner tự ẩn khi header bình thường — patch entity khi feed restored |

Hiển thị `data_as_of` từ response khi có.

---

## 10.4 Sync Conflict (409 SYNC_CONFLICT)

> **SoT:** Tech Spec §24.4.1 — full refresh GET, không merge partial GĐ1

**Trigger:** PATCH/DELETE Watchlist hoặc Alert trả `409 SYNC_CONFLICT`

**Hành vi UI (theo thứ tự):**

1. **Abort** watchlist local edits / form draft đang dang dở
2. Hiện loading overlay **cục bộ** trên danh sách liên quan
3. Tự động GET lại (`/watchlist/tabs/{id}/items` hoặc `/alerts`)
4. **Overwrite** `watchlist.*` / `alerts` từ server — patch `entities.*` nếu snapshot kèm giá
5. Toast: "Danh mục đã được cập nhật từ thiết bị khác"
