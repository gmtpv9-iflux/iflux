# 0. UI ARCHITECTURE PRINCIPLE (ABSOLUTE RULE)

## 0.1 Core Definition

UI iFlux =

> **Deterministic Projection Layer of Entity Store (05) rendered through Design System (06)**

---

## 0.2 Three-Layer Execution Model

```id="u0-model"
05 ENTITY RUNTIME (Source of Truth)
        ↓
07 UI ARCHITECTURE (Composition + Binding)
        ↓
06 DESIGN SYSTEM (Visual Rendering)
```

---

## 0.3 HARD CONSTRAINT

UI is:

* ❌ NOT data owner
* ❌ NOT logic owner
* ❌ NOT event processor
* ✔ ONLY projection layer

---

# 1. RUNTIME BINDING CONTRACT (NEW — CRITICAL GAP FIX)

## 1.1 Entity Binding Rule (FROM 05 §0.5 — LOCKED)

UI MUST bind strictly to:

| Entity     | Source                     |
| ---------- | -------------------------- |
| stocks     | `entities.stocks[ticker]`  |
| sectors    | `entities.sectors[id]`     |
| ecosystems | `entities.ecosystems[id]`  |
| flow       | `entities.*.flow[subject]` |

👉 UI CẤM:

* tạo local state mirror của entity
* derive business logic từ raw event

---

## 1.2 Snapshot vs WSS Priority (STRICT FROM 05 §0.5.3)

| Scenario  | Rule                                     |
| --------- | ---------------------------------------- |
| Boot      | Snapshot seeds entity store              |
| Runtime   | WSS patches entity store                 |
| Reconnect | Snapshot **OVERRIDES ALL WSS**           |
| Conflict  | Snapshot wins if reconnect window active |
| Stale WSS | MUST discard during snapshot window      |

---

## 1.3 Event Processing Rule (FROM 05 §9)

```text
WSS → batch (200ms) → entity patch → UI render
```

UI MUST NOT:

* process raw WSS events
* store channel-level state
* reorder event streams

---

## 1.4 Deduplication Rule (INV-E01)

* Every event MUST be deduped by `event_id`
* Applies to:

  * WSS
  * Push notification
  * user-events sync stream

# 2. UI COMPOSITION MODEL

## 2.1 Layer Hierarchy

```text
Page
  ↓
Module (Screen Section)
  ↓
Widget (Data Intelligence Unit)
  ↓
Card (Entity Renderer)
  ↓
Component (UI Unit)
  ↓
Primitive (Design System 06)
```

---

## 2.2 Strict Responsibility Split

| Layer     | Responsibility                         |
| --------- | -------------------------------------- |
| Widget    | Data transformation ONLY (no UI logic) |
| Card      | Entity presentation ONLY               |
| Component | UI structure ONLY                      |
| Primitive | Visual rendering ONLY                  |

---

## 2.3 Forbidden Rules

* Widget ❌ không được format UI
* Card ❌ không được fetch data
* Component ❌ không được compute ranking / flow / score
* Page ❌ không được biết API source

---

# 3. WIDGET CONTRACT (SYNC WITH 06 + 05)

## 3.1 Widget Definition

Widget =

> Deterministic transformer from Service Layer → Entity list → Card list

---

## 3.2 Widget Input/Output Contract

```ts
Widget {
  input: {
    filters,
    context,
    time_range
  },

  source: Service (04_API / 06 Service Layer),

  output: {
    cards: Card[],
    meta: {
      updated_at,
      ranking_version
    }
  }
}
```

---

## 3.3 Widget Rule

* ✔ Can aggregate data
* ✔ Can rank entities
* ❌ Cannot render UI
* ❌ Cannot contain design logic

---

# 4. CARD MODEL (ENTITY PRESENTATION LAYER)

## 4.1 Card Rule

Card = 1 primary entity projection

Examples:

* StockCard → Stock entity
* SectorCard → Sector entity
* FlowCard → Flow entity

---

## 4.2 Card Constraints

* No API call
* No business logic
* No aggregation
* Only formatting of entity fields

---

## 4.3 Card Output Contract

```ts
Card {
  entity_id,
  type,
  fields: {
    formatted only (NO computation)
  },
  state: derived from entity store (05)
}
```

---

# 5. COMPONENT MODEL (SYNC WITH 06)

## 5.1 Component Rule

Component = UI structural unit only

Examples:

* StockRow
* PricePanel
* FlowBar
* StickerBadge

---

## 5.2 Component Constraints

* MUST use Design System tokens (06)
* MUST NOT access API or service
* MUST receive fully resolved props only

---

# 6. DESIGN SYSTEM BINDING (FROM 06 — LOCKED)

## 6.1 Token Rule

UI MUST use:

* Primitive tokens
* Semantic tokens
* Component tokens

❌ NO raw hex / px

---

## 6.2 Motion Rule (05 §0.4 + 06 §2)

| State     | Behavior             |
| --------- | -------------------- |
| Normal    | Pulse allowed        |
| Stale     | opacity only         |
| Degraded  | motion OFF           |
| Reconnect | reset all animations |

---

## 6.3 Z-Index Contract (06 §3.4)

UI MUST follow:

* pulse < warning < modal < toast
* no override allowed

---

# 7. RUNTIME STATE PROJECTION (CORE 05 INTEGRATION)

## 7.1 Entity Store Dependency

UI reads ONLY:

```text
entities.*
meta.*
watchlist.*
alerts.*
```

---

## 7.2 Projection Rule

```text
Entity Store (05)
    ↓
Card Mapping
    ↓
Component Props
    ↓
Design System Render (06)
```

---

## 7.3 No Direct State Rule

UI MUST NOT:

* store price state locally
* store flow state locally
* store rank state locally

# 9. RUNTIME FLOW (FULL LOCKED PIPELINE)

```text
BOOT
 → snapshot load (05)
 → hydrate entity store
 → build widgets
 → render cards
 → mount components (06)
 → connect WSS
 → stream delta
 → patch entity store
 → re-render affected components only
```

---

# 10. RECONNECT & RECOVERY (05 HARD SYNC)

## 10.1 RULE SET

| Step | Action                         |
| ---- | ------------------------------ |
| 1    | freeze WSS input               |
| 2    | discard stale events           |
| 3    | snapshot override entity store |
| 4    | rebuild UI projection          |
| 5    | resubscribe WSS                |
| 6    | resume streaming               |

---

## 10.2 UI Behavior

* preserve scroll
* preserve navigation stack
* reset animations
* no full re-render

---

# 11. DEGRADATION MODE (05 + 06 SYNC)

| Layer       | Behavior                   |
| ----------- | -------------------------- |
| Data        | frozen last valid snapshot |
| UI          | no pulse                   |
| Motion      | OFF                        |
| Banner      | ON                         |
| Interaction | enabled                    |

---

# 12. PERFORMANCE RULES

* No full tree re-render on WSS
* Only entity-key diff updates
* Batch 200ms (transport layer)
* Card reuse mandatory
* Component reuse mandatory
