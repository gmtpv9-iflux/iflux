## 0. GIẢI THÍCH THUẬT NGỮ — SERVICE & COMPONENT

> **Quy ước:** Cột **Tên (EN)** = tên service trong code/deploy. Cột **Tên Việt** = cách gọi khi trao đổi nội bộ. **GĐ1** = Go-live v1.0 (Mobile + Web + Admin).

| Tên (EN) | Tên Việt | GĐ1 | Vai trò (1 câu) | Input → Output chính |
|---|---|:---:|---|---|
| **Data Ingestion Service** | Dịch vụ Thu thập & Chuẩn hóa Dữ liệu | ✅ | Nhận tick từ Data Provider, validate, enrich, **phân loại Chủ thể (`subject`)**, ghi Redis giá RT, publish Kafka | Provider stream → `ticks` + `stock:{ticker}` Redis |
| **Money Flow Engine** | Engine Dòng tiền | ✅ | Tích lũy Mua/Bán/Ròng theo entity + subject; ranking dòng tiền; **không** phân loại subject | `ticks` → Redis `flow:*` + `flow-updates` |
| **Synthetic Index Engine** | Engine Chỉ số Tổng hợp | ✅ | Tính Ig, Pg, Breadth cho Ngành/Họ; cập nhật ranking hiệu suất | `ticks` + `ecosystem-changed` → Redis `index:*` + `index-updates` |
| **Alert Engine** | Engine Cảnh báo | ✅ | So khớp điều kiện Alert user; cooldown; phát sự kiện trigger | `ticks`, `index-updates`, `flow-updates` → `alert-triggers` |
| **Notification Service** | Dịch vụ Gửi Thông báo | ✅ | Gửi push/mobile/web/email từ alert trigger — **không** tính toán nghiệp vụ | `alert-triggers` → FCM / APNs / Web Push |
| **API Gateway** | Cổng API | ✅ | Xác thực JWT, rate limit, routing REST, flag degraded mode | Client HTTP → Market/User/Admin backend |
| **Web BFF** | Lớp API cho Web | ✅ | Backend-for-Frontend: SSR, trang public, OG meta, anonymous tier — **không** duplicate engine | Next.js routes → gọi Market/User API nội bộ |
| **Auth & Subscription Service** *(User & Auth)* | Dịch vụ Xác thực & Gói cước | ✅ | OTP, JWT, IAP, thanh toán Web, tier Free/Premium/Elite | `/auth/*`, `/subscriptions/*` → PostgreSQL `users` |
| **Watchlist Service** *(module trong User)* | Dịch vụ Danh mục Theo dõi | ✅ | CRUD tab/mã watchlist + optimistic lock; publish sync event | REST `/watchlist/*` → PostgreSQL + `user-events` |
| **Market Service** | Dịch vụ Dữ liệu Thị trường (REST) | ✅ | API đọc giá, ngành, họ, ranking, OHLCV — **App + Web dùng chung** | Redis/TimescaleDB → REST `/market`, `/sectors`, `/stocks` |
| **Admin Service** | Dịch vụ Quản trị | ✅ | CMS taxonomy (Sector/Ecosystem), user ops, feature flags, audit | Admin UI → PostgreSQL + `ecosystem-changed` |
| **Platform Sync Service** | Dịch vụ Đồng bộ Đa nền tảng | ✅ | Fanout thay đổi Watchlist/Alert/tier cho App/Web (SSE/cache invalidate) | `user-events` → client sync ≤ 5s |
| **WebSocket Gateway** | Cổng WebSocket | ✅ | Push real-time cho **App** — consume Kafka, fanout theo channel subscribe | `ticks`, `index-updates`, `flow-updates` → WSS client |
| **Persistence Worker** | Worker Ghi Dữ liệu Lịch sử | ✅ | Cuối phiên: flush Redis/Kafka → TimescaleDB; job snapshot ranking | Redis `flow:*`, Kafka `ticks` → `stock_ohlcv`, `money_flow`, `ranking_snapshot` |
| **Analytics / Event Tracking** | Theo dõi Sự kiện & KPI | ✅ | Thu sự kiện sản phẩm (share, alert, session); rollup KPI Admin | `analytics-events` → batch job → ADM-OPS-002 |
| **Late Tick Processor** | Bộ xử lý Tick Muộn | ✅ | Tick phiên cũ → ghi TimescaleDB trực tiếp, bypass Redis intraday | `ticks.late` → TimescaleDB |
| **SEO Service** | Dịch vụ SEO kỹ thuật Web | ✅ | sitemap, robots.txt, canonical — §24.6; cron/Web infra | Config → public SEO assets |
| **Story / Narrative Service** | Dịch vụ Chủ đề (Story) | ⏸ GĐ2 | Layer 4 — narrative investing; **chưa triển khai GĐ1** | — |
| **Community Service** | Dịch vụ Cộng đồng | ⏸ GĐ2+ | Tương tác xã hội, feed — **chưa triển khai GĐ1** | — |

### 0.1 Phân biệt dễ nhầm

| Cặp | Khác nhau thế nào |
|---|---|
| **Data Ingestion** vs **Money Flow Engine** | Ingestion = cửa vào: chuẩn hóa + gán `subject`. Money Flow = tính dòng tiền từ tick đã enrich — **không** re-classify. |
| **Alert Engine** vs **Notification Service** | Alert = quyết định *có* trigger không. Notification = *gửi* push/email — consume `alert-triggers`, không qua WebSocket market. |
| **API Gateway** vs **Web BFF** | Gateway = cổng chung mọi REST (auth, limit). BFF = lớp riêng Web (SSR, SEO, public page) — gọi API nội bộ. |
| **Market Service** vs **Engine** | Market Service = **đọc** state đã tính (Redis/DB) phục vụ API. Engine = **tính** state realtime từ Kafka tick. |
| **WebSocket Gateway** vs **Market Service** | WSS = push stream App. Market Service = pull REST (Web poll ~30s, App snapshot + WSS). |
| **Persistence Worker** vs **Engine** | Worker = ghi **lịch sử** cuối phiên. Engine = state **trong phiên** trên Redis. |
| **Watchlist Service** vs **Platform Sync** | Watchlist = lưu & API CRUD watchlist. Platform Sync = broadcast thay đổi sang client khác (App↔Web). |
| **Auth & Subscription** vs **Entitlement** | Auth Service = đăng nhập + gói cước DB. Entitlement = **quy tắc** tier nào được dùng feature nào (§4.5) — enforce tại Gateway. |

> **File 03 (Service Spec Sheets)** sẽ mở rộng từng service: endpoint owned, health check, deploy unit, dependency — dựa trên bảng trên.  
> **Deploy boundary GĐ1 vs GĐ2 Reserved:** Tech Spec §2.2.

```sql
-- Chốt quy ước Entity ID theo Tech Spec §3.6:
-- stock: "HPG" | sector: "sec:5" | ecosystem: "eco:7"

CREATE TABLE sectors (

    ticker VARCHAR(10) PRIMARY KEY, -- uppercase
    name VARCHAR(255) NOT NULL,
    exchange VARCHAR(10) NOT NULL, -- HOSE, HNX, UPCOM
    sector_id INT REFERENCES sectors(id),
    ecosystem_id INT REFERENCES ecosystems(id) NULL,
    shares_outstanding BIGINT NOT NULL,
    lot_threshold BIGINT DEFAULT 1000000000, -- VND

CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

CREATE TABLE watchlist_items (
    id BIGSERIAL PRIMARY KEY,
    user_id UUID REFERENCES users(id),
    tab_name VARCHAR(50) DEFAULT 'Theo dõi',
    ticker VARCHAR(10) REFERENCES stocks(ticker),
    position SMALLINT DEFAULT 0,
    version INT DEFAULT 1, -- Optimistic lock §24.4.1
    UNIQUE(user_id, tab_name, ticker)
);

CREATE TABLE alerts (
    id BIGSERIAL PRIMARY KEY,
    user_id UUID REFERENCES users(id),
    entity_type VARCHAR(20) NOT NULL, -- stock, sector, ecosystem
    entity_id TEXT NOT NULL, -- Theo §3.6 (HPG, sec:5, eco:7)
    conditions JSONB NOT NULL,
    status VARCHAR(20) DEFAULT 'active', -- active, disabled, triggered

);
```

### 1.3 Persistence Flush Contract

> **Owner duy nhất ghi TimescaleDB (GĐ1):** Persistence Worker (+ batch job `ranking-snapshot`). Engine **không** ghi trực tiếp `money_flow` / `stock_ohlcv` / `ranking_snapshot`.

| Target Table | Flush Job | Schedule (ICT) | Redis / Kafka Source | Conflict Key (UPSERT) | Strategy |
|---|---|---|---|---|---|
| `stock_ohlcv` (1m) | `session-stock-ohlcv-flush` | 15:55–16:05 | Kafka topic `ticks` (session_date = today, retention 24h) + validate close vs `stock:{ticker}` | `(time, ticker, timeframe)` | **UPSERT** — ghi đè nến 1m cùng bucket |
| `money_flow` | `session-flow-flush` | 15:55–16:05 | Redis `flow:{entity_type}:{entity_id}:{subject}:{session_date}:buy\|sell` | `(time, entity_type, entity_id, subject)` | **UPSERT** — `time` = session close 15:00 ICT |
| `ranking_snapshot` | `ranking-snapshot` | 16:30 | Redis `ranking:stock:flow:{date}`, `ranking:sector:flow:{date}`, `ranking:{type}:performance` | `(time, ranking_type, entity_id)` | **INSERT** — snapshot bất biến; `ON CONFLICT DO NOTHING` |

**Batch size:** 500 rows/transaction (mặc định GĐ1).

**Idempotency flush job:**

| Cơ chế | Giá trị |
|---|---|
| Job marker | Redis `flush:done:{job_name}:{session_date}` — SETNX trước khi chạy |
| Rerun cùng ngày | UPSERT tables → kết quả giống nhau; ranking_snapshot → skip duplicate |
| Partial fail | Commit theo batch; batch lỗi retry; marker chỉ set khi **toàn job** success |

**Ghi chú:** `group_index_ohlcv` (1m) do **Synthetic Index Engine** async upsert trong phiên (Tech Spec §5.1) — **không** thuộc flush job trên. Rollup 1D+ do scheduled jobs §4.4.

```sql
-- Snapshot ranking cuối phiên (bổ sung GĐ1)
CREATE TABLE ranking_snapshot (
    time            TIMESTAMPTZ  NOT NULL,
    ranking_type    VARCHAR(30)  NOT NULL,  -- stock_flow, sector_flow, sector_performance, ...
    entity_id       TEXT         NOT NULL,
    rank_position   INT          NOT NULL,
    score           NUMERIC(20,6) NOT NULL,
    session_date    DATE         NOT NULL,
    PRIMARY KEY (time, ranking_type, entity_id)
);
SELECT create_hypertable('ranking_snapshot', 'time');
```

## 2. REDIS KEY SCHEMA (In-Memory State)

Tuân thủ **Single-Writer Principle** (§19.2).

| Key Pattern | Data Type | Writer Service | Mục đích |
| :--- | :--- | :--- | :--- |
| `stock:{ticker}` | `HASH` | Data Ingestion | Giá RT, shares, ref_price |
| `index:{type}:{id}` | `HASH` | Synthetic Engine | Ig, Pg, Breadth của Ngành/Họ |
| `flow:{entity}:{id}:{subject}:{date}:{side}` | `STRING` | Money Flow Engine | Tích lũy Buy/Sell ròng (INCRBY) |
| `ranking:{type}:performance` | `ZSET` | Synthetic Engine | Score = Pg. Sort Ngành/Họ/Mã |
| `ranking:{type}:flow:{date}` | `ZSET` | Money Flow Engine | Score = Net Value. Ranking dòng tiền |
| `alert:cooldown:{alert_id}` | `STRING` | Alert Engine | Chặn spam notification (TTL) |
| `dedup:{flow\|index}:{event_id}` | `STRING` | Engine tương ứng | Chống trùng tick (TTL 24h) |
| `system:maintenance` | `STRING` | Admin Service | Flag bảo trì hệ thống |

## 3. EVENT CONTRACT (Kafka Message Bus)

> **Luật:** Mọi record Kafka **bắt buộc** bọc Standard Envelope (§3.0). Payload nghiệp vụ nằm trong field `data`.

### 3.0 Standard Envelope (mọi topic)

SoT: Tech Spec §4.3.1.

```json
{
  "event_id":       "uuid-v4",
  "event_type":     "TICK | INDEX_UPDATE | FLOW_UPDATE | watchlist.item_added | tier_changed | ...",
  "event_time":     "2026-06-21T09:15:32.123Z",
  "process_time":   "2026-06-21T09:15:32.187Z",
  "source":         "data-ingestion | synthetic-index | money-flow | user-service | ...",
  "schema_version": "v1",
  "data":           { }
}
```

| Field | Bắt buộc | Ghi chú |
|---|---|---|
| `event_id` | ✅ | UUID v4 — dedup key (§3.4) |
| `event_type` | ✅ | Loại sự kiện — consumer routing |
| `event_time` | ✅ | Thời điểm nghiệp vụ (ISO 8601 UTC) |
| `process_time` | ✅ | Thời điểm producer ghi message |
| `source` | ✅ | Service produce |
| `schema_version` | ✅ | `"v1"` GĐ1 — breaking change → tăng version |
| `data` | ✅ | Payload theo từng topic (§3.4–§3.13) |

**Versioning:** Consumer reject `schema_version` không support → DLQ. Thêm field mới trong `data` = non-breaking.

### 3.1 Delivery & Idempotency

SoT: Tech Spec §4.2.1, §6.1.

| Quy tắc | Giá trị |
|---|---|
| Delivery semantics | **At-least-once** — consumer phải idempotent |
| Dedup key | `event_id` (UUID trong envelope) |
| Dedup store | Redis `dedup:flow:{event_id}` / `dedup:index:{event_id}` — TTL **24h** (§2) |
| Hành vi khi trùng | Skip xử lý, commit offset — **không** cộng dồn lần 2 |
| Rebuild / replay | Bật dedup khi replay Kafka — tránh double-count (§6.1) |

**Producer:** Mỗi tick/event mới phải có `event_id` unique. **Consumer:** Check dedup **trước** khi mutate Redis/DB.

SoT: Tech Spec §4.2. Mọi topic File 02 nhắc tới **phải** có trong bảng này.

| Topic | Kafka message key | Mục đích |

### 3.3.1 Topic `ticks` — Normalized + Enriched Market Event

> **SoT chốt:** Không có topic `raw-ticks` hay `enriched-ticks` riêng. Topic duy nhất **`ticks`** chứa tick đã qua Data Ingestion.

| Giai đoạn | Owner | Output |
|---|---|---|
| Normalize | Data Ingestion | Validate schema, clock skew (§18.3), gán `event_id` |
| Enrich | Data Ingestion | Lookup `sector_id`, `ecosystem_id`, `lot_threshold` |
| Classify Subject | **Data Ingestion** | Gán field `subject` — §4.3.3 Tech Spec (**không** phải Money Flow Engine) |
| Publish | Data Ingestion | Envelope §3.0 → topic **`ticks`** |
| Side effect | Data Ingestion | Ghi `stock:{ticker}` Redis (writer duy nhất — §19.2) |

**Engines** (Money Flow, Synthetic Index, Alert) **chỉ consume `ticks`** — không re-classify `subject`.

### 4.4 Ranking & Score Formulas (LOCKED — GĐ1)

> Dev **không** tự định nghĩa công thức. SoT chi tiết: Tech Spec §5.1, §5.3, §5.4, §6.1.

| Metric | Công thức | Redis / API field | Owner |
|---|---|---|---|
| **Pg (Performance %)** | `mean([(price_i - ref_price_i) / ref_price_i] × 100)` trên mã active; skip halted (§5.3 EC-02); IPO ngày 1: Pg mã = 0, không vào mean (EC-01) | `index:*.pg`, API `pg` | Synthetic Index Engine |
| **Performance Score (sort)** | `pg_score = round(Pg × 100, 2)` | ZSET `ranking:{sector\|ecosystem}:performance` | Synthetic Index Engine |
| **Money Flow Score** | `net_value = buy_value - sell_value` (VND, per entity + subject + session_date) | ZSET `ranking:*:flow:{date}` score = `net_value` | Money Flow Engine |
| **Strength (Sticker "Str")** | `strength = round(Pg × 100)` — hiển thị Contextual Sticker | `sector_sticker.strength`, WSS `sticker_update` | API derive từ Redis `index:*` |
| **Rank** | Thứ hạng 1-based từ ZSET descending (`pg_score` hoặc `net_value`) | `rank`, `sector_sticker.rank` | Engine + API |
| **Trend** | So sánh `rank` hiện tại vs `ranking_snapshot` phiên trước: `up` / `down` / `flat` | `trend` | API |
| **Ig (Synthetic Index level)** | `Ig = Σ(price_i × shares_i) / divisor` | `index:*.ig` | Synthetic Index Engine |

> **Power Circle (UI):** Vòng trực quan map từ **Strength** (`0–300+` scale = `Pg × 100`) — **không** có công thức riêng GĐ1.  
> **Health Score (BRD):** GĐ1 alias **`Pg`** cho ranking ngành/họ — composite đa yếu tố defer GĐ2.

## 5. DEVELOPMENT BOUNDARIES (Luật chơi cho Dev)

1.  **Strict Field Names:** Tuyệt đối không dùng `stockCode` thay cho `ticker`, `netFlow` thay cho `net_value`. Mọi thứ phải dùng `snake_case`.
2.  **Optimistic Locking:** Khi cập nhật Watchlist/Alert, client **bắt buộc** gửi kèm `version`. Server **bắt buộc** check version trước khi UPDATE.
3.  **No Direct Redis Write:** API Service không được phép ghi vào các key `flow:*` hay `index:*`. Chỉ được ghi vào key `api:*` (cache).
4.  **Decimal Precision:** Toàn bộ giá trị tiền tệ trong DB phải dùng `NUMERIC` hoặc `BIGINT` (nhân 100 nếu cần), không dùng `FLOAT/DOUBLE` để tránh sai số lũy kế.
5.  **Kafka Envelope bắt buộc:** Producer **không** publish payload thuần. Mọi message phải có `event_id`, `schema_version`, `data` (§3.0).
6.  **Idempotent Consumer:** Engine xử lý tick/event **một lần** — dedup bằng `event_id` trước khi ghi Redis (§3.1).
7.  **Kafka Topics Registry:** Producer/consumer **chỉ** dùng topic có trong §3.2 — schema tối thiểu theo §3.4–§3.13.
8.  **REST path:** Chỉ implement endpoint trong §4.2 — không alias path tự phát.
9.  **Ranking formula:** Chỉ dùng công thức §4.4 — không tự tính score.
