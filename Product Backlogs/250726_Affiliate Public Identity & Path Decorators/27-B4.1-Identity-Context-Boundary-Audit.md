## 2. Model đúng (ADR-AFF-007 — đã khóa)

```text
Identity Context (Owner / NavigationContext)
          │
          │  ownerPublicId = IFLYZ2NC
          ▼
ShellUrlWriter.decorate(canonical)
          │
          ├── /                          → /IFLYZ2NC
          ├── /cong-dong                 → /IFLYZ2NC/cong-dong
          ├── /co-phieu/MSN              → /IFLYZ2NC/co-phieu/MSN
          ├── /cong-dong/bai-viet/slug   → /IFLYZ2NC/cong-dong/bai-viet/slug
          └── /{future-route}            → /IFLYZ2NC/{future-route}
```

**Identity là parent · page/route là child.**  
Writer đã implement đúng hướng này — **không** cần sửa Context/Lifecycle cho case MSN / bài viết.

## 3. A — Nơi quyết định có prefix hay không

### 3.1 Source of truth (đúng tầng)

| Layer | Module | Vai trò | Identity-aware? |
|-------|--------|---------|-------------------|
| **Context Owner** | `navigation-context.js` | Lưu `ownerPublicId` | ✅ |
| **Lifecycle** | `pnc-lifecycle.js` | create/transfer/deactivate · restore session | ✅ |
| **Single Writer** | `shell-url-writer.js` | `decorate(canonical)` · `navigate()` · `syncBarWithOwner()` | ✅ |
| **Zone policy** | `shell-url-writer.isApplicationZone()` | App zone vs Exclusion | ✅ (route-registry based) |
| **Route registry** | `IfluxRoutes` (`iflux-platform-boot.js`) | `detectRoute()` · prefix match trên `route.public` | ✅ generic |

**Không có** function riêng kiểu `buildPublicUrl(pageKey)` gắn prefix theo page.  
Prefix decision **chỉ** ở `decorateCanonical()`:

```text
owner = getContext().ownerPublicId
if owner && isApplicationZone(canonical) → '/' + owner + canonical
```

### 3.2 Bypass thực tế (sai tầng — root cause)

| Bypass | Module | Pattern | Decorated? |
|--------|--------|---------|------------|
| **SEO href factory** | `seo-url.js` | `stockHref()` · `postHref()` · `sectorHref()` … | ❌ canonical only |
| **Feed / entity UI** | `community-ui.js` · `community-store.js` · `market-heatmap.js` … | `<a href="` + SeoUrl | ❌ |
| **Search** | `iflux-header-search.js` | entity → SeoUrl | ❌ |
| **Route-key only** | `IfluxRoutes.to(key)` | shell header · W1/W2 CTAs | ✅ |
| **Programmatic** | `IfluxShellUrlWriter.navigate(canonical)` | pricing checkout · post comments fallback | ✅ |

**~17 module** gọi `IfluxSeoUrl.*Href()` — **không** qua Writer.  
Đây là lý do `/co-phieu/MSN` và `/cong-dong/bai-viet/...` mất prefix khi click từ affiliate namespace.

### 3.3 Gap API consumer (MR-1 side effect)

MR-1 cho phép consumer:

- `Routes.to(routeKey)` — decorated ✅ nhưng **chỉ route key**, không nhận `/co-phieu/MSN`
- `navigate(canonical)` — decorated ✅ nhưng chỉ programmatic, không sinh `href`

MR-1 **cấm** consumer gọi `decorate()` trực tiếp → **không có public API** để sinh decorated href cho arbitrary canonical path.

Kết quả: B4 Wave 1–2 thêm `routeUrl('community')` từng chỗ — **page-scoped patch**, không đóng identity boundary.

## 4. B — Phân loại route (Runtime · không dùng Sitemap Admin)

Phân loại theo **Application Zone policy** (`IfluxRoutes.detectRoute` + prefix match), **không** theo Admin Page Settings / Sitemap.

```text
Public Runtime Routes (Application Zone)
│
├── Identity Root
│     /{publicId}                    → canonical /
│
├── Community
│     /cong-dong
│     /cong-dong/bai-viet/*
│     /cong-dong/chu-de|tac-gia|danh-muc/*
│
├── Market Entity
│     /co-phieu/*
│     /nganh/*
│     /he-sinh-thai/*
│     /cau-chuyen/*
│
├── App pages (route registry)
│     /thi-truong · /dong-tien · /goi-cuoc · /nha-cua-toi · …
│
└── Future (vd. /bao-cao · /portfolio)
      → zone:'app' trong ROUTES = auto isApplicationZone ✅
      → href vẫn bypass nếu dùng SeoUrl/hardcode ❌
```

### Câu trả lời AC-ID-CONTEXT-002

> Nếu ngày mai thêm `/bao-cao`, có cần sửa decoration rule?

| Tầng | Cần sửa? |
|------|----------|
| Writer / Zone policy | **Không** — thêm entry `ROUTES` zone `app` |
| SeoUrl / consumers | **Có** — mọi link mới qua canonical factory sẽ lại bypass Writer |

→ Kiến trúc **chưa đạt** identity-inherit-by-default.

## 6. Timing gap — `syncBarWithOwner` vs shell boot

`pnc-lifecycle.init()` chạy tại **DOMContentLoaded** (script inject `<head>`).

`IfluxRoutes` load **sau** — async qua `shell-boot.js` (ESM).

Khi `syncBarWithOwner()` chạy sớm:

```javascript
// shell-url-writer.isApplicationZone()
if (global.IfluxRoutes) { /* detectRoute → zone app */ }
if (path === '/' || path === '/guest') return true;
return false;  // ← /co-phieu/MSN · /cong-dong/bai-viet/* = FALSE
```

→ Bar sync **bỏ qua** entity/article path lúc init.  
Sau khi Routes load xong, **không có** recall `syncBarWithOwner()`.

Đây là lý do có thể thấy context còn (store) nhưng bar vẫn clean trên detail pages.

## 8. Exit criteria mới (đề xuất khóa vào Conformance Report)

### AC-ID-CONTEXT-001 — Identity MUST NOT depend on Page

```gherkin
Given  Guest · NavigationContext.ownerPublicId = IFLYZ2NC
When   Open any Application Zone route (entity · article · list · future)
Then   Address bar prefix = IFLYZ2NC
And    Internal links from that page inherit IFLYZ2NC
```

### AC-ID-CONTEXT-002 — New public route MUST NOT require navigation rule change

```gherkin
Given  New route /bao-cao added to ROUTES (zone: app)
When   Developer uses standard consumer href API (not SeoUrl bypass)
Then   Links auto-decorate under active Owner
And    No per-page migration PR required
```

### AC-ID-CONTEXT-003 — All public consumers inherit identity context

```gherkin
Given  Active Owner context
When   Audit grep: runtime href generation paths
Then   100% funnel through Writer (Routes.to · navigate · approved href API)
And    0 production paths: SeoUrl.*Href → raw <a> without decorate
```

## 9. Khuyến nghị — không patch theo page

### Tạm dừng

- **B4 Wave 3** (`iflux-web-ui.js` · `iflux-guest-shell.js` · `iflux-header-search.js`)

### Mở B4.2 — Consumer Href Funnel (cần Owner chốt approach)

**Option A (ưu tiên — 1 điểm sửa):**  
Funnel `IfluxSeoUrl.*Href()` → `IfluxRoutes.href(canonical)` (API mới, wrap Writer.decorate)  
→ 17+ consumer inherit tự động · future routes free

**Option B:**  
Document + enforce `Routes.href(canonical)` · migrate từng caller (giống W3–W4 mở rộng — **không đạt AC-ID-CONTEXT-002**)

**Option C (shell-only):**  
Recall `syncBarWithOwner()` sau shell-ready + global `<a>` intercept  
→ fragile · không khuyến nghị làm primary

**Đồng thời (hotfix timing):**  
Shell-ready hook → `syncBarWithOwner()` — **không** thay funnel consumer

### Frozen (giữ nguyên)

- `navigation-context.js` · `pnc-lifecycle.js` · ownership transitions
- `decorate()` logic — đã identity-centric
