## GIẢI THÍCH THUẬT NGỮ

| Thuật ngữ | Nghĩa tiếng Việt | Giải thích trong ngữ cảnh PEP |
|---|---|---|
| **PEP** (Product Execution Plan) | Kế hoạch triển khai sản phẩm | Trả lời "Build cái gì, theo thứ tự nào, trong bao lâu" — cầu nối giữa PRD (what) và thực thi Sprint. |
| **MVP** (Minimum Viable Product) | Sản phẩm khả dụng tối thiểu | Tập con tính năng đủ để người dùng trải nghiệm giá trị cốt lõi — nhỏ hơn toàn bộ P0 scope. |
| **DAG** (Directed Acyclic Graph) | Đồ thị có hướng không vòng | Sơ đồ thể hiện quan hệ phụ thuộc giữa các Epic — Epic sau chỉ build được khi Epic trước hoàn thành phần cốt lõi. |
| **Critical Path** | Đường tới hạn | Chuỗi phụ thuộc dài nhất xuyên suốt DAG — delay bất kỳ node nào trên critical path đều delay Go-live. |
| **Sprint** | Chu kỳ phát triển | Chu kỳ 2 tuần — đơn vị lập kế hoạch trong PEP này. |
| **Sprint 0** | Sprint thiết lập | Sprint đặc biệt trước khi build tính năng — dùng để setup môi trường, kết nối data, dựng CI/CD. |
| **Milestone** | Cột mốc | Điểm kiểm tra quan trọng để đánh giá tiến độ và quyết định tiếp tục/điều chỉnh. |
| **Blocker** | Tắc nghẽn | Vấn đề làm dừng hoàn toàn tiến độ của một Epic hoặc Sprint nếu không được giải quyết. |
| **Buffer Sprint** | Sprint đệm | Sprint dự phòng trong lịch để xử lý nợ kỹ thuật, bug, và các việc phát sinh — không dùng để thêm tính năng mới. |
| **Epic** | Nhóm tính năng lớn | Tập hợp các FR liên quan trong PRD — đơn vị lập kế hoạch ở cấp cao. |
| **Synthetic Index Engine** | Động cơ chỉ số tổng hợp | Engine tính toán OHLCV cho Ngành/Họ — xem PRD Epic 01 §5.2. |
| **Money Flow Engine** | Động cơ dòng tiền | Engine xử lý và phân loại dòng tiền 4 chủ thể — xem PRD Epic 01 §5.3. |
| **Go-live** | Phát hành chính thức | **Mobile App + Website + Admin Panel** live; SLA/KPI dashboard hoạt động — PRD §2.4. |
| **Soft launch** | Phát hành mềm | Phát hành giới hạn (invite-only hoặc 1 sàn) trước Go-live chính thức để kiểm tra thực tế. |
| **Platform Parity** | Parity đa nền tảng | App và Web cùng nghiệp vụ cốt lõi — khác **trọng tâm**, không thiếu tính năng (BRD §19). |
| **Go-live Gate (GL-xx)** | Cổng phát hành | Điều kiện bắt buộc pass trước Go-live — §6.2. |
| **Golden Path** | Luồng vàng | Khách/user đi trọn: khám phá → xem thị trường → mã/ngành → Watchlist → Alert — trên **App hoặc Web**. |
| **DRI** (Directly Responsible Individual) | Người chịu trách nhiệm trực tiếp | Một người — không phải team — accountable cuối cùng cho Epic; §2.4. |
| **ADM-OPS-xxx** | Màn hình vận hành Admin | ADM-OPS-001 (SLA summary), ADM-OPS-002 (Product KPI), ADM-OPS-006 (Data Provider) — PRD Epic 12–13. |

## 1. Quan hệ tài liệu & SoT

PEP là tài liệu **phái sinh từ PRD v1.2.1** — không tự phát sinh yêu cầu mới. Mọi Epic, tính năng và scope trong PEP đều trace về PRD → BRD v2.1 → IA v1.4.

```
BRD v2.1 (WHY + WHAT nghiệp vụ)
    │
    ▼
IA v1.4 (WHERE — App / Web / Admin)
    │
    ▼
PRD v1.2.1 (WHAT + AC — 13 Epic)
    │
    ▼
PEP v2.0 (WHEN + ORDER)  ← tài liệu này
    │
    ▼
Tech Spec (HOW kỹ thuật)
```

**Quy tắc cập nhật:**

| Tình huống | Hành động |
|---|---|
| PRD thay đổi scope | PEP phải review và cập nhật §3 (MVP) + §5 (Roadmap) |
| Tính năng bị defer | Cập nhật bảng MVP §3.2 + điều chỉnh Sprint tương ứng trong §5 |
| Phát hiện dependency mới | Cập nhật DAG §4 + re-sequence Roadmap §5 |
| Sprint bị delay | Không tự ý cắt tính năng — báo PM để quyết định trade-off |

## 2. Executive Summary

### 2.1 Mục tiêu Release

**Go-live v1.0** là phát hành **ba kênh user/ops** cùng lúc:

| Kênh | Trọng tâm | Giá trị Go-live |
|---|---|---|
| **Mobile App** | Decision Cockpit + Action | Real-time, Alert Push, Dashboard Widget |
| **Website** | Discovery + Narrative + Acquisition | SEO, public pages, WEB-SHR, funnel đăng ký |
| **Admin + Observability** | Governance + Operations | Taxonomy CMS, user ops, **SLA + Product KPI** |

Giá trị cốt lõi user (cả App và Web):

- Biểu đồ nến Ngành và Họ cổ phiếu (Synthetic Index Candlestick)
- Dòng tiền 4 nhóm chủ thể
- Context Layer — Ngành + Họ tại màn chi tiết mã
- Watchlist + Alert đồng bộ đa nền tảng (Platform Parity)
- Share Web-first → WEB-SHR landing

**Hành trình User theo kênh (trọng tâm — không phải thiếu tính năng):**

| Giai đoạn | Web (Discovery + Narrative) | App (Decision Cockpit + Action) |
|---|---|---|
| **SEE** | SEO, landing, public entity pages | Push/open app → Dashboard real-time |
| **UNDERSTAND** | Narrative layout, chart refresh ~30s | Candlestick Ngành/Họ, Context Layer real-time |
| **ACT** | Watchlist, Alert (browser/email), đăng ký Premium | Watchlist, Alert Push, Action Bar |
| **PERSONALIZE** | WEB-HOME logged-in | Dashboard Widget (layout **không** sync sang Web) |

> **Platform Parity:** Cùng account, cùng Watchlist/Alert/gói — user chọn kênh theo ngữ cảnh; Admin + Observability đo SLA/KPI trên cả hai.

- DRI có quyền phân công sub-task cho team member, nhưng không được delegate trách nhiệm DoD.
