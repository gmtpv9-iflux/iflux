# 0. EXECUTION PRINCIPLE (ABSOLUTE RULE)

## 0.1 Core Definition

Frontend Execution Engine =

> **Deterministic runtime system that executes 05 (data), renders 07 (structure), using 06 (visual rules)**

---

## 0.2 Hard Constraint

FE Engine:

* ❌ không sở hữu state business
* ❌ không xử lý logic domain
* ❌ không xử lý WSS raw stream trực tiếp
* ✔ chỉ execute deterministic pipeline

---

## 0.3 Execution Model

```text
05 (Entity Runtime)
   ↓
08 (Execution Engine)
   ↓
07 (UI Composition)
   ↓
06 (Design System Render)
   ↓
DOM/UI Output
```

---

# 1. APPLICATION RUNTIME LOOP (CORE ENGINE)

## 1.1 Main Loop

```id="rt-loop"
BOOT
 → INIT RUNTIME ENGINE
 → LOAD SNAPSHOT (05)
 → HYDRATE ENTITY STORE
 → INIT WIDGET REGISTRY (07)
 → INIT COMPONENT TREE
 → APPLY DESIGN SYSTEM (06)
 → CONNECT WSS STREAM
 → ENTER EVENT LOOP
```

---

## 1.2 Event Loop Execution

```text
WSS / REST EVENT
   ↓
Normalize Event
   ↓
Entity Store Patch (05)
   ↓
Diff Engine
   ↓
Widget Recompute (07)
   ↓
Card Update
   ↓
Component Re-render
   ↓
DOM Patch (06 rendering rules)
```

---

## 1.3 Hard Rule

> UI rendering MUST ALWAYS follow entity diff, never event input.

---

# 2. ENTITY STORE ENGINE (05 INTEGRATION)

## 2.1 Single Source of Truth

```ts
state = {
  entities,
  meta,
  watchlist,
  alerts
}
```

---

## 2.2 Mutation Rule

* ONLY allow mutation through:

  * snapshot override
  * WSS patch
  * server sync response

❌ UI local mutation forbidden

---

## 2.3 Snapshot Override Rule

```text
Reconnect / Boot:
snapshot ALWAYS overrides entity store before WSS resume
```

---

## 2.4 WSS Processing Rule

* batch window: 200ms
* dedup: event_id (INV-E01)
* discard stale during reconnect window
* apply only latest per entity key per batch

---

# 3. DIFF ENGINE (CRITICAL CORE)

## 3.1 Diff Principle

FE MUST compute:

```text
previous_entity_state → next_entity_state
→ minimal diff
→ UI patch
```

---

## 3.2 Diff Scope

| Level      | Update type     |
| ---------- | --------------- |
| Field      | price, ig, flow |
| Entity     | stock, sector   |
| Collection | watchlist list  |

---

## 3.3 No Full Re-render Rule

❌ forbidden:

* full page re-render on WSS

✔ allowed:

* per-entity patch update only

---

# 4. WIDGET EXECUTION ENGINE (07 INTEGRATION)

## 4.1 Widget Lifecycle

```text
Entity Store update
   ↓
Widget selector triggered
   ↓
Recompute widget output
   ↓
Emit Card list
```

---

## 4.2 Widget Execution Rule

* input = entity subset only
* output = cards only
* no UI logic
* deterministic output

---

## 4.3 Widget Recompute Trigger

| Trigger       | Action                      |
| ------------- | --------------------------- |
| entity update | recompute affected widget   |
| snapshot load | full recompute              |
| reconnect     | full invalidate + recompute |

---

# 5. CARD RENDER ENGINE (07 → 06 LINK)

## 5.1 Card Contract

Card = pure projection of entity

---

## 5.2 Render Rule

```text
Card → Component → Design System Render
```

---

## 5.3 Update Scope

* card updates ONLY if entity diff affects it
* no global refresh

---

# 6. COMPONENT RENDER ENGINE (06 INTEGRATION)

## 6.1 Component Rule

Component = stateless UI renderer

---

## 6.2 Props Rule

Component MUST receive:

* fully resolved entity fields
* no raw service calls
* no computed business logic

---

## 6.3 Design System Binding

Component MUST:

* use tokens only
* use motion rules from 06
* obey z-index contract
* obey degraded/stale rules

---

# 7. REAL-TIME STREAMING ENGINE (05 WSS CORE)

## 7.1 Stream Pipeline

```text
WSS Event
 → Normalize
 → Batch (200ms)
 → Dedup (event_id)
 → Entity Patch
 → Diff Engine
 → UI Update
```

---

## 7.2 Channel Rule

* UI MUST NOT subscribe by component
* UI subscribes by entity domain only

---

## 7.3 Discard Rule (CRITICAL)

During reconnect:

* ALL WSS events are discarded
* no queue replay allowed
* snapshot overrides everything

---

# 8. RECONNECT ENGINE (05 CRITICAL LOGIC)

## 8.1 Sequence

```text
1. Freeze WSS input
2. Discard incoming events
3. Fetch snapshot
4. Override entity store
5. Rebuild widget outputs
6. Re-render UI diff
7. Resume WSS
```

---

## 8.2 UI Behavior

* preserve scroll
* preserve navigation
* reset animation state
* no full DOM reset

---

# 9. RENDER SCHEDULER

## 9.1 Batch Rule

* 200ms batch window for WSS
* coalesce multiple updates per entity

---

## 9.2 Priority Queue (sync 09 §3.6)

| Priority | Type                                      |
| -------- | ----------------------------------------- |
| P0       | snapshot override                         |
| P1       | reconnect discard window                  |
| P2       | Push / `user-events` / 409 sync response  |
| P3       | WSS market (price, index, flow, sticker)  |
| P4       | UI chrome / pulse animation only          |

Same-tick: execute highest priority first; lower frames in the same batch window dropped if superseded by P0–P2.

---

# 10. DESIGN SYSTEM EXECUTION (06 INTEGRATION)

## 10.1 Token Resolution

* resolved at render time
* no runtime mutation of tokens

---

## 10.2 Motion Control (sync 06 §5.3)

| State     | Motion                                              |
| --------- | --------------------------------------------------- |
| normal    | pulse enabled                                       |
| stale     | opacity 0.6 **+ pulse still runs** until degraded   |
| degraded  | motion OFF — transport RT stop per 05 §9.4          |
| reconnect | reset animation timers — no replay historical pulse |

---

## 10.3 Z-index enforcement

Engine MUST enforce:

* no override allowed
* strict layering per 06

---

# 11. PERFORMANCE ENGINE

## 11.1 Rendering Constraint

* no full tree render
* per-entity update only
* memoized component reuse

---

## 11.2 Memory Rule

* entity store is ephemeral session state
* snapshot rehydrates full state
* no duplication across widgets/components

---

# 12. SYSTEM GUARANTEES

## 12.1 Determinism Guarantee

Same input (05 + WSS stream) → same UI output

---

## 12.2 Consistency Guarantee

* entity store = single truth
* UI = projection only
* no divergence allowed

---

## 12.3 Real-time Guarantee

* max 200ms lag batch window
* per-entity update only
